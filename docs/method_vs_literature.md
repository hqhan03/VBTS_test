# 이 캠페인의 학습 방식이 문헌과 어디서 갈리는가 — 2026-09-10

`force_estimation.md` 와 `force_estimation_digit.md` 가 쓴 전처리·학습을, DIGIT/GelSight 로
힘을 추정한 공개 연구들과 나란히 놓고 본다. 목적은 "우리가 맞다/틀리다" 가 아니라
**어느 선택이 표준과 다르고, 그 차이가 결론의 어디에 걸리는가**를 분명히 해 두는 것이다.

## 2. 같은 것

- **기준 이미지 차감.** Sparsh 도 DIGIT/GelSight 에 배경 차감을 전처리로 쓴다 — "무접촉이
  어떤 모습인지 모델에 주기 위해". 우리와 같은 이유이고, `reference_collect.png` 로 런마다
  자기 기준을 쓰는 것은 오히려 더 엄격하다(프로브 그림자 문제, `campaign_protocol.md` §4.7).
- **오차의 자릿수.** 우리 9DTact 의 Fz MAE 36 mN 은 Sparsh 가 DIGIT 에서 보고한 RMSE 36 mN 과
  같은 자리다. 지표(MAE 대 RMSE)와 범위가 달라 직접 비교는 아니지만, **우리 숫자가 문헌 밖에
  있지 않다**는 확인은 된다.
- **로봇 압입 + F/T 라벨.** 세 연구 모두 같은 방식이다.

## 3. 다른 것 — 그리고 그 차이가 어디에 걸리는가

### 3.1 시험 분할이 문헌보다 무르다 (가장 큰 차이)

Sparsh 는 **압자 모양을 남겨두고**(sharp·sphere 학습 → flat 시험), FeelAnyForce 는 **처음 보는
실물**로 시험한다. 우리는 **같은 압자(ball8)의 뒤쪽 사이클**을 시험으로 쓴다.

우리가 재는 것은 "같은 접촉을 다시 봤을 때의 내삽" 이고, 그들이 재는 것은 "새 모양으로의
일반화" 다. **둘은 다른 양이고, 우리 숫자를 일반화 성능으로 읽으면 안 된다.**

다만 이 캠페인의 질문에는 우리 분할이 맞다: **해상도가 오차를 어떻게 바꾸는가**를 보려면 다른
모든 것이 고정돼야 하고, 압자를 바꾸면 압흔의 공간 주파수가 함께 바뀌어(§3.6) 해상도 효과와
섞인다. 일반화까지 보려면 `data_wishlist.md` #1(날카로운 압자)·#9(접촉 위치)가 필요하다.

### 3.2 단일 프레임 — 시간 정보를 안 쓴다

Sparsh 는 **t 와 t−5 두 프레임을 채널로 붙여** 6 채널로 넣는다. 즉 모델이 "지금 얼마나 눌렸나"
뿐 아니라 "얼마나 빨리 눌리고 있나" 를 본다. 우리는 단일 프레임이다.

**이것은 우리 데이터로 바로 시험할 수 있다.** 그리고 시험할 이유가 있다: §3.4 의 오차 예산에서
전단 바닥이 라벨의 시간적 모호성과 얽혀 있었고(창 안 이동), 두 프레임을 주면 그 모호성의 일부가
관측 가능해진다. `data_wishlist.md` 에 "수집 없이 학습만으로" 항목으로 추가한다.

### 3.3 입력 정규화를 안 한다

우리는 화소를 **0–255 실수 그대로** 넣는다(9DTact 원본 `dtact_dataset.py` 를 따랐다).
ImageNet 사전학습 ResNet 은 채널별 평균·표준편차로 정규화된 입력을 전제하므로, 사전학습의
이점을 일부 버리는 선택이다. 첫 합성곱이 스케일을 흡수할 수 있어 치명적이지는 않지만
**표준과 다르다.**

**결론에 걸리는 정도**: 모든 해상도에 같은 전처리를 썼으므로 **해상도 비교는 그대로 유효**하다.
영향을 받는 것은 "이 센서의 절대 정확도" 뿐이고, 그것을 주장하려면 정규화를 켜고 다시 재야 한다.

### 3.4 아무도 해상도를 쓸지 않는다

세 연구 모두 224×224(또는 그에 준하는 고정 크기) 하나만 쓴다. **해상도를 변수로 놓고 쓸어본
연구를 찾지 못했다.** 이 캠페인의 기여가 거기 있고, 결과는 그 관행을 부분적으로 정당화한다:
전단 오차가 80–320 px 에서 최저이므로 **224 는 전단 최적 근처**다. 반면 Fz 는 48 px 까지
평평하므로, 법선력만 필요한 응용에서는 224 가 과하다.

### 3.5 회색 대 색

우리 기본 표현은 9DTact 조리법을 따라 **회색 차영상**이다. 문헌은 RGB 를 유지한다(Sparsh 는
2 프레임 × 3 채널). `force_estimation_digit.md` §3 에서 재보니 **DIGIT 에서 색을 살리면
오차가 4–10 % 준다** — 낮은 해상도일수록 이득이 크다. 즉 문헌 쪽 관행이 DIGIT 에서는 옳고,
회색 기본값은 9DTact 에서 물려온 것이다. 두 표현을 모두 돌려 둔 것이 다행이다.

### 3.6 힘 범위가 좁다

우리는 0–2 N(법선), 명령 0.5 N(전단)이다. FeelAnyForce 는 **15 N** 까지 간다. 좁은 범위는
의도된 선택이다 — 54 유닛을 같은 span 에서 비교해야 하고(`campaign_protocol.md`), 넓히면
겔이 상한에 먼저 닿는 유닛이 생긴다. 대가는 **상대 오차가 커 보인다**는 것이다: 36 mN 은
2 N 의 1.8 % 지만 15 N 이면 0.24 % 다. **범위를 밝히지 않은 상대 오차 비교는 무의미하다.**
